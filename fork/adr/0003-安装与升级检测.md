# 0003. 安装方式与内置升级检测

- **Status：** Accepted
- **日期：** 2026-08-31
- **Fork-ADR：** 0003

## Context

ADR 0001 只发 GitHub 上的裸二进制：`codex-x86_64-pc-windows-msvc.exe` 和 `codex-x86_64-unknown-linux-gnu`。用户自己放到 PATH。

上游 TUI/CLI 在 **release** 构建里（debug 整模块不编译）会做升级检测：

- 入口：`codex-rs/tui/src/updates.rs` 的 `get_upgrade_version`，启动约 20 小时查一次，写入 `~/.codex/version.json`
- 默认 `check_for_update_on_startup = true`（`codex-rs/core/src/config/mod.rs`）
- `CARGO_PKG_VERSION` 为 `0.0.0` 时当成源码构建，直接跳过。我们发版会盖成真版本，于是检测会跑起来
- 查询 `https://api.github.com/repos/openai/codex/releases/latest`，标签只认 `rust-v` 前缀（`update_versions.rs`）
- 版本比较只看 `major.minor.patch`，`0.152.0-alpha.6.wa.1` 和 `0.152.0-alpha.6.wa.2` 会被当成一样新
- 安装通道是 `InstallMethod::Other`（PATH 里一颗 exe）时，弹窗里的「立即更新」不会出现（没有 `UpdateAction`），但历史栏仍可能显示「Update available」，链接指向 `openai/codex`
- 若将来被识别成 standalone，按钮会跑 `https://chatgpt.com/codex/install.sh` / `install.ps1`，装的是官方包，把 fork 盖掉
- `codex doctor` 同样去打官方 latest

官方安装脚本还校验 `x.y.z[-alpha…]`，不接受 `.wa.N`。我们不改那些脚本。

内置自动替换二进制以后再说。

## Decision

安装：只支持手动。到 [WAcry/codex Releases](https://github.com/WAcry/codex/releases) 下载当前平台资产，改名为 `codex` / `codex.exe`，放到 PATH 里已有的目录。不要跑官方 `install.sh` / `npm i -g @openai/codex` / `brew upgrade --cask codex` 来装这个 fork。

内置升级：关掉。`get_upgrade_version` / `get_upgrade_version_for_popup` 在本 fork 里直接返回 `None`，这样不请求 `openai/codex`，不弹更新，不往历史栏塞官方链接。`codex doctor` 的 updates 行不再探测 latest。用户要换版本就自己再下一份二进制。

不在本 ADR 做：下载资产覆盖当前 exe、fork 安装脚本、改 `scripts/install/*`、npm/brew 通道、把检测改去打 `WAcry/codex`。这些进 `fork/backlog.md`。

若以后重做检测，必须同时改这几处，不能只改 URL：仓库、`wa-v` 标签解析、含 `.wa.N` 的比较、GitHub `/releases/latest` 不包含 prerelease（我们按上游 alpha 发的包常是 prerelease）、更新动作不能再指向 chatgpt.com 安装脚本。

## Paths

```text
codex-rs/tui/src/updates.rs
codex-rs/cli/src/doctor/updates.rs
fork/README.md
fork/OVERLAY.md
fork/backlog.md
fork/adr/0003-安装与升级检测.md
```

不改 `scripts/install/install.sh`、`install.ps1`、`tui/src/update_action.rs`、`tui/src/history_cell/notices.rs`。

## Coupling

上游若重写 `get_upgrade_version` 或把检测挪到别的 crate，同步时按本 ADR 把「直接返回 None」再打进去。不要为了同步把探测重新打开。

发版仍盖 workspace version（ADR 0001）。没有本补丁的 release 包会去问官方 latest。

## Reapply

打开 `codex-rs/tui/src/updates.rs`，确认 `get_upgrade_version` 开头仍是 fork 的提前返回。`cli/src/doctor/updates.rs` 的 latest 探测同样跳过。文件被上游改乱就只把这两处逻辑加回，不要顺手改 notices 里的 URL。

## 如何确认

```text
# release 二进制（盖过版本，不是 0.0.0）
# 启动 TUI：无 Update available，无更新弹窗
# 断网或抓包：不应出现 api.github.com/repos/openai/codex/releases
# codex doctor：updates 行不报「newer version is available」来自官方 latest
```

debug / `cargo run` 本身就不编 `updates` 模块，不能当这项的证明。

## Upstream

TUI：`codex-rs/tui/src/updates.rs`、`update_prompt.rs`、`update_action.rs`、`app/startup.rs`。Doctor：`codex-rs/cli/src/doctor/updates.rs`。安装脚本：`scripts/install/install.sh`、`scripts/install/install.ps1`。

## 后果

用户不会被引导去装官方 Codex。也不会在 TUI 里一键升到下一份 WAcry 包，只能看 Releases 手动换文件。doctor 对「是否过期」沉默。
