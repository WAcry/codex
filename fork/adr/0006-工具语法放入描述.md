# 0006. 工具语法放入描述

- **日期：** 2026-09-07
- **Fork-ADR：** 0006

## 背景与决策

为便于切换不支持 grammar 约束解码的模型，工具输入语法统一写入模型可见的 description。所有模型采用同一规则，包括 GPT。假定模型能够理解并遵循完整语法，直接搬移原有语法文本即可。

`apply_patch` 和 Code Mode 的 `exec` 保留完整 Lark 语法，以代码块附在各自的描述中；`apply_patch` 的环境 ID 语法仍按现有条件生成。共享 `FreeformTool` 仅保留名称、描述与延迟加载字段。工具仍接收原始文本，沿用现有解析器。

[OpenAI 官方 SDK](https://github.com/openai/openai-node/blob/master/src/resources/responses/responses.ts) 将 custom tool 的 `format` 定义为可选，默认接收自由文本。此决策迁移语法说明的位置，格式由模型遵循说明和工具解析器校验。它不保证仅支持 JSON function tools 的接口能直接接受 custom tools。

## 路径与重应用

以下路径相对 `codex-rs/`：

- `core/src/tools/handlers/apply_patch_spec.rs`、`core/src/tools/code_mode/execute_spec.rs`：语法文本放入 description。
- `tools/src/responses_api.rs`、`tools/src/lib.rs`、`tools/src/tool_search.rs`：精简共享工具定义及搜索文本。

同步上游时，检查所有新增或修改的工具。凡使用 Lark 或 regex 输入语法的工具，都必须在采用时把完整语法移到 description，保持直接调用、命名空间、延迟加载和 Code Mode 中可见，并更新 OVERLAY。此规则适用于所有模型和 provider。

## 如何确认

按 ADR 0002，合并后在 `main` 验证：

- `codex-core` 与 `codex-tools` 的 lib 测试：工具定义、环境 ID、序列化及搜索。
- `code_mode_can_apply_patch_via_nested_tool`：普通模式及仅 Code Mode 模式的请求均携带语法说明，实际写入文件成功。
- `code_mode_exposes_and_dispatches_namespaced_custom_tools`：Lark 描述随命名空间工具传递，直接和嵌套调用成功。
- `tool_search_returns_deferred_custom_tool_and_routes_follow_up_call`：regex 描述随延迟加载结果传递，后续调用成功。

## 上游等价实现后清理

上游统一采用描述中的语法说明后，删除重复补丁、本 ADR、README 索引及 OVERLAY 条目，并同步精简 ADR 0002 和对应 CI 测试命令。
