# 0001. Fork 版本号与 GitHub 发布

- **Status：** Accepted
- **日期：** 2026-08-31
- **Fork-ADR：** 0001

## Context

上游在 `main` 上把 `codex-rs/Cargo.toml` 的 `[workspace.package] version` 钉在 `0.0.0`，发版靠打 `rust-vX.Y.Z` 标签，并要求被 tag 的那次提交里 workspace 版本与标签一致。标签还会触发 `rust-release.yml`：自托管 runner、macOS 签名公证、Azure Windows 签名、R2、npm `@openai/codex`、WinGet。

[WAcry/codex](https://github.com/WAcry/codex) 没有这些 runner、environment 和 secrets。原样打 `rust-v*` 会空等或整条失败。我们需要能下载的 Windows / Linux 二进制，同时日常 `main` 继续跟上游，少改 `Cargo.toml`。

## Decision

版本号：`{上游完整版本}.wa.{N}`。

例子：上游 `0.152.0-alpha.6` 的第一次 fork 发布是 `0.152.0-alpha.6.wa.1`；上游稳定版 `0.152.0` 是 `0.152.0-wa.1`。同一上游版本再发一包，把最后的 `N` 加一。换到更新的上游版本后，`N` 从 `1` 再起。

Git 标签：`wa-v` 加上上面的版本，例如 `wa-v0.152.0-alpha.6.wa.1`。不要用上游的 `rust-v*` 前缀。

`main` 上的 `codex-rs/Cargo.toml` 保持 `0.0.0`。发布 job 从标签解析出版本，只在本次 checkout 里改 workspace version，再 `cargo build --release --bin codex`。改动不提交。

发布触发：在已合进 `main` 的提交上打 annotated tag，推到 `origin`。`.github/workflows/fork-release.yml` 监听 `wa-v*`。

产物（第一期）：

- `codex-x86_64-pc-windows-msvc.exe`
- `codex-x86_64-unknown-linux-gnu`
- `SHA256SUMS`
- 发布说明里写提交 SHA 和对应上游版本

Linux 用 GNU 动态链接，在 `ubuntu-24.04` 上本地编。Windows 用 GitHub-hosted `windows-latest`。二进制不签名。不发 npm、R2、WinGet，不更新 `latest-alpha-cli`。

上游 `.github/workflows/rust-release*.yml` 等文件原样保留。在 GitHub 上禁用，见 ADR 0002。

## Coupling

标签格式和 `fork-release.yml` 里的校验必须一致。上游若改 `cargo build --bin codex` 的 crate 布局、rusty_v8 预编译件下载方式（`.github/actions/setup-rusty-v8`），发布 job 会编不过。

`codex --version` 在未走发布流程的本地/CI debug 构建里仍是 `0.0.0`。以 GitHub Release 里的包为准。

## Reapply

若 `fork-release.yml` 在同步时被删：从本 ADR 和当前 overlay 把文件加回来。不要去改 `rust-release.yml` 来“修”上游发版。

标签校验坏了：先改 workflow 里的正则，再改本 ADR 开一篇新决策，不要口头换版本规则。

## 如何确认

```text
# 标签必须被拒绝（缺 .wa.N）
# 合法标签推到 origin 后，Actions 里 fork-release 成功，
# Release 上有 Windows exe、Linux ELF、SHA256SUMS。
# 解压/下载后：codex --version 等于标签去掉 wa-v 前缀。
```

本地抽查（有对应二进制时）：

```text
.\codex-x86_64-pc-windows-msvc.exe --version
```

## Upstream

上游发版入口：`.github/workflows/rust-release.yml`。标签约定见该文件顶部注释。workspace 版本：`codex-rs/Cargo.toml` 的 `[workspace.package]`。

## 后果

用户从 GitHub Releases 装 fork 构建，不能走官方 `npm i -g @openai/codex` 或 `releases.openai.com` 安装脚本来拿我们的改动。macOS 和 ARM 第一期没有包。GNU Linux 二进制依赖目标环境的 glibc。每次发版要人工选上游版本号并推 tag。
